KIỂM THỬ & BÀN GIAO — PHẦN VỠ GIỌNG / HỤT HƠI (TTS)
====================================================

Mục tiêu chứng minh
-------------------
- Đoạn dài đọc trơn hơn, không gãy rõ ở chỗ nối chunk.
- Không còn: nối ba chấm sau mỗi chunk, repetition penalty quá cao, nối PCM thô từng đoạn.

Chuẩn bị (một lần)
------------------
1. git pull, mở venv đúng project.
2. pip install -r AI_Service/tts_service/requirements.txt (torch + torchaudio cùng dòng phiên bản).
3. AI_Service/tts_service/model/ có đủ config.json, model.pth, vocab.json, file giọng ref (vd giongnuhanoi6s.wav).

Cách test có số (khuyến nghị)
-----------------------------
0) Không có model.pth trên máy: chạy dry-run (đã fix đường dẫn repo + UTF-8 console Win):

  cd AI_Service/tts_service
  python export_cau_test_wav.py --dry-run

  → Ghi tts_test_output/dry_run_chunk_report.txt (cách tách chunk từng dòng cau-test.txt).

1) Baseline (nếu còn nhánh/tag cũ): checkout commit trước khi sửa → chạy script xuất WAV vào tts_test_output/truoc_fix/
2) Sau sửa: checkout nhánh hiện tại → xuất vào tts_test_output/sau_fix/

  cd AI_Service/tts_service
  python export_cau_test_wav.py --out ../../tts_test_output/sau_fix --voice nuhanoi

  Cần có: model/model.pth, config.json, vocab.json, file giọng ref (vd giongnuhanoi6s.wav).

Input mặc định: docs/cau-test.txt (18 dòng).

3) Nghe A/B: cùng số 001.wav … 018.wav hai thư mục; ghi dòng nào còn lỗi (số 00x + mô tả ngắn).

Deliverables để chốt tiền (vd 5 triệu cho mục này)
-------------------------------------------------
- Mã: nhánh/commit có tts_pipeline.py, sửa tts_service.py (+ server.py nếu dùng).
- Script: export_cau_test_wav.py + docs/cau-test.txt.
- Kết quả: folder tts_test_output/sau_fix/001.wav … 018.wav (hoặc zip gửi khách).
- Báo cáo ngắn 1 trang: trước/sau (nghe được), câu nào vẫn yếu + lý do nếu có.

Ngoài phạm vi mục này
---------------------
- Song ngữ sâu (G2P / tách EN-VI) — giai đoạn sau.
- Train lại checkpoint XTTS.

Ghi chú
-------
- AI không nghe thay được; “pass” do người nghe và ký nhận.
